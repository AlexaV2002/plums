## Что уже есть

- NestJS/Prisma/PostgreSQL и Windows-клиент Flutter; авторизация JWT, ротация refresh-токенов, профиль, серверы, приглашения, участники, баны, каналы и сообщения.
- Роли с шестью серверными правами, управление ролями и назначениями во Flutter, realtime-события. Права канала пока общие для участников, а не отдельные для каждой роли.
- Backend и Flutter для личных диалогов: поиск, создание, история, отправка, удаление и realtime. Договорённости и ограничения API — в `docs/DM_API.md`.
- Защита Socket.IO-комнат и восстановление сессии/истории после переподключения. Полный финальный регресс на устройствах после всех текущих изменений ещё не завершён.

Нового диалога сейчас достаточно, чтобы он появился у второго участника до первого сообщения. Изменение этого поведения отложено пользователем. У ЛС отдельно остаётся риск повторной отправки при потере HTTP-ответа.

Не реализованы загрузка вложений и аватаров, реальное голосовое аудио, видеокружки, непрочитанные/уведомления, восстановление и смена пароля. Мобильная готовность не подтверждена. Сверка требований и границы проверок — `docs/TZ_COMPLIANCE.md`; более старый `docs/AI_PROJECT_CONTEXT.md` может содержать устаревшие статусы.

## Как продолжать

1. Прочитать `CLAUDE.md`, этот документ и только файлы, связанные с конкретной задачей. Существующие пользовательские изменения сохранять; коммит и push делать только по отдельному запросу.
2. Для новой работы по изображениям B04 сначала согласовать схему и контракт. Нужна новая миграция; существующие миграции не менять. PostgreSQL пользователя не использовать для разрушительных тестов.
3. Для доступа и ролей учитывать, что `manageRoles` позволяет выдать себе другие серверные права, а `manageServer` включает удаление сервера. Изменять эту политику только в рамках согласованной задачи.
4. При ручной LAN-проверке следовать `docs/LAN_TESTING.md`. Адрес `API_BASE_URL` задаётся при сборке Flutter; `localhost` на втором ПК указывает на него самого.
5. Не читать и не выводить содержимое `.env`, токены и пароли. Результаты проверок сообщать фактически, с указанием того, что ещё не проверено.
