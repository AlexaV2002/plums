# Изображения в каналах

B04: изображения JPEG, PNG и WebP в текстовых каналах. Максимум четыре изображения в сообщении, до 10 МиБ на файл и 40 миллионов пикселей. Backend определяет формат по содержимому, декодирует и перекодирует файл; исходное имя и указанный клиентом MIME-тип не используются как доказательство формата.

Все запросы требуют Bearer access token. Загрузка требует членства, права просмотра и отправки в текстовый канал. Получение прикреплённого изображения повторно проверяет текущее членство, право просмотра и то, что сообщение не удалено. Владелец сервера обходит ограничения канала согласно существующей модели прав.

| Метод | Путь | Описание |
|---|---|---|
| POST | `/channels/:channelId/attachments` | Multipart, поле `file`; ответ `{id, originalName, mimeType, sizeBytes}`. Изображение пока не прикреплено. |
| POST | `/channels/:channelId/messages` | Существующий DTO дополняется `attachmentIds` (до четырёх). Пустой `content` допустим при наличии вложений. Привязка к сообщению выполняется в транзакции. |
| GET | `/attachments/:id/content` | Только прикреплённое изображение при действующем доступе к сообщению; ответ с `Cache-Control: private, no-store` и `X-Content-Type-Options: nosniff`. |
| DELETE | `/attachments/:id` | Отменить только собственную незакреплённую загрузку; ответ 204. Прикреплённые или чужие загрузки этим способом не удаляются. |

История канала, ответ создания и события `message:new` / `message:update` содержат `attachments` с публичными метаданными. Закрытый `storageKey` в API и события не включается. Повтор с тем же `clientMessageId` допустим только с тем же текстом и набором ID изображений; при неизвестном результате отправки нужно повторять тот же запрос, не удаляя загрузки.

Байты хранятся за интерфейсом `AttachmentStorage`; текущий адаптер локальный. По умолчанию он использует `storage/attachments` относительно рабочего каталога backend. Для стабильной работы и резервного копирования следует задать абсолютный `ATTACHMENT_STORAGE_DIR` вне публичной раздачи и сохранить его между перезапусками. S3-адаптер ещё не реализован; локальная файловая система отдельных экземпляров backend не является общим хранилищем.

Незакреплённая загрузка истекает через 24 часа. Удаление метаданных записывает ключ в независимую очередь через триггер, в том числе при каскадном удалении; фоновая задача повторяет удаление и проверяет старые файлы-сироты. После ошибки до записи метаданных файл удаляется сразу при возможности, иначе его уберёт проверка сирот. Тесты с `NODE_ENV=test` используют хранилище внутри `backend/.tmp` и не должны указывать на пользовательское хранилище.

Для запуска нужны Prisma Client и применённая миграция `20261102020000_add_channel_attachments`; существующие миграции не меняются. Интеграционные тесты запускайте только на отдельной тестовой PostgreSQL с совпадающими `DATABASE_URL` и `TEST_DATABASE_URL`, как требует `backend/test/ensure-test-database.ts`.
