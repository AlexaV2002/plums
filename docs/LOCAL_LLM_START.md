# Plums: локальный помощник в Continue

## Запуск

Связка: VS Code + Continue + LM Studio. Модель уже скачана: Qwen3-Coder 30B Q6_K.
Сервер работает на локальном адресе http://127.0.0.1:1234/v1.
API-ключ для этой конфигурации не требуется. Все запросы модели идут в LM Studio.

В PowerShell при необходимости запусти:

```powershell
lms server start --port 1234
lms runtime select 'llama.cpp-win-x86_64-vulkan-avx2@2.49.0'
lms load qwen/qwen3-coder-30b --identifier plums-local --context-length 8192 --gpu 0.3 --parallel 1 --ttl 3600 -y
```

Не запускай повторную загрузку, если `lms ps` уже показывает `plums-local`.
TTL выгружает неиспользуемую модель через час; команда загрузки возвращает её в память.
Профиль Continue: `Plums Local`, модель `Plums Local Qwen3-Coder 30B`, режим Agent.
Копия конфигурации: `.continue/agents/new-config.yaml`.
Рабочая пользовательская конфигурация: `%USERPROFILE%\.continue\config.yaml`.

Начальные настройки рассчитаны на Ryzen 9 7950X, 32 ГБ RAM, GTX 1080 Ti 11 ГБ.
Контекст 8192 токена общий для запроса и ответа. Не прикладывай весь проект.
Если контекст переполнен, открой новый чат и передай одну задачу и нужные файлы.
Сообщение Continue `Message exceeds context limit` означает, что история чата
стала слишком длинной. Открой новый чат: повторная отправка того же сообщения
в переполненный чат не очистит историю. Не запускай `git diff` без имени файла:
в рабочей копии много изменений, и он выдаёт сотни строк. Используй сначала
`git diff --stat`, затем `git diff -- <путь-к-одному-файлу>`.
Continue здесь запускает команды через Windows PowerShell 5.1. Не используй
`&&`, `ls -la` и команды Unix. Одна команда на один вызов инструмента.
Из корня проекта проверка backend выглядит так:

```powershell
npx.cmd tsc --noEmit --incremental false -p backend/tsconfig.build.json
npm.cmd --prefix backend test -- src/dm/dm.service.spec.ts --runInBand
```

Команда `tsc ... src/dm/dm.service.ts` не заменяет проверку проекта через
`tsconfig.build.json`: она может проигнорировать настройки проекта.
Скорость и качество сложных правок зависят от модели; проверяй предложенный diff.
При настройке CUDA-движок 2.66.0 падал с кодом 3221226505; установленный
Vulkan 2.49.0 успешно загрузил Qwen3-Coder и выполнил тестовый вызов инструмента
через `/v1/chat/completions` за 3,4 секунды (короткий запрос, не скорость работы с проектом).
Тест не выполнял инструмент и не менял файлы приложения.
На компьютере выбран Vulkan-движок для GGUF; это также влияет на другие GGUF-модели LM Studio.
GPT-OSS в ходе проверки падал; рабочий профиль использует Qwen3-Coder.

## Правила работы над проектом

- Отвечай по-русски. Начинай с `git status --short`.
- Терминал Continue — Windows PowerShell 5.1; запускай команды по одной, без
  `&&` и без Unix-флагов вроде `ls -la`.
- Не запускай `git diff` без пути. Сначала смотри `git diff --stat`, затем diff
  одного файла текущей задачи. Для незакоммиченного нового файла используй `rg`
  и небольшие диапазоны строк. Ограничивай вывод команд примерно 120 строками.
- Сохраняй существующие незакоммиченные изменения; не выполняй reset/clean.
- Backend: NestJS, Prisma, PostgreSQL. Клиент: Flutter; API через Dio, realtime через Socket.IO.
- Бери одну небольшую задачу. Сначала прочитай связанный controller/service/DTO, а для realtime ещё gateway и обработчик клиента.
- Используй `rg` и небольшие диапазоны строк. Не загружай `client/lib/main.dart` целиком: в нём более 6600 строк.
- Сохраняй контракты API. Авторизацию, членство и права проверяй на backend.
- События отправляй после успешной записи в БД. Учитывай переподключения и повторные события.
- Не меняй UI, generated-файлы, зависимости и применённые миграции без необходимости для задачи.
- Не читай `.env`, ключи и пароли. Не выполняй commit/push без команды пользователя.
- `docs/AI_PROJECT_CONTEXT.md` и `docs/TZ_COMPLIANCE.md` отстают от кода по ролям и DM.
- `docs/BIONIC_START.md` содержит старую отдельную задачу; она не является текущим заданием.

Проверки после backend-правок из `backend`:

```powershell
npx.cmd tsc --noEmit --incremental false -p tsconfig.build.json
npm.cmd test -- --runInBand
```

После Flutter-правок из `client`: `flutter analyze` и относящиеся к задаче тесты.
Перед отчётом: `git diff --check` и просмотр собственного diff.
Указывай фактические результаты, не выдавай unit-тесты с моками за проверку реальной БД.

## Состояние при передаче, 29 октября 2026

В коде есть авторизация, серверы, приглашения, каналы, сообщения, роли, модерация и presence.
Backend DM добавлен в незакоммиченной рабочей копии; завершённый клиент DM не обнаружен.
До настройки локальной модели: TypeScript прошёл, backend 86 тестов прошли;
Flutter analyze сообщил 26 замечаний, единственный widget-тест упал.
Это исходные результаты аудита, а не обещание результата после будущих изменений.

Известные проблемы для отдельных последующих задач:

1. `MessagesGateway`, `ServersGateway`, `ChannelsGateway`: вступление в комнаты без проверки JWT и прав.
2. `dm.service.ts`: прежняя ошибка include со скалярными `userA/userB` исправлена
   в рабочей копии, но ответ создания диалога ещё нужно сверить с ответом списка.
3. `auth.service.ts`: ротация refresh-токена не защищена от параллельного использования.
4. Клиент после reconnect восстанавливает комнату сервера, но не канала; identify использует захваченный accessToken.
